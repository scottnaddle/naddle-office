# AI 작성 흐름 구현 계획

> 상태: **초안 v0.1** — 설계 검토용. 코드 변경 없음.
> 전제: 기존 문서 앱(docs·slides·sheets 등)의 인터페이스를 유지하고, 각 앱 **안의 AI 패널**에서 같은 작성 흐름이 진행된다. 통합 스튜디오 화면은 만들지 않는다. 영상은 같은 셸의 새 앱 종류로 추가한다.
> 기준: main `7690521a`, 업스트림 훅 원장 counted **78 / 상한 90**. P0-3 원장·검사기(#24)가 먼저 머지되어야 각 슬라이스의 훅 수를 CI에서 검증할 수 있다(P0-3 자체 counted +0).

---

## 1. 목표 · 비목표

**목표**

- 문서 종류가 달라도 사용자 경험이 같다: **템플릿 → 브리프(질문+개요 승인) → 생성(진행) → 검토/QC → 편집·내보내기**.
- 왼쪽 AI 패널은 공통 카드로, 오른쪽은 종류별 캔버스(문서 페이지·덱·영상 플레이어/장면)로 나눈다.
- 새 기능은 업스트림 테스트를 고치지 않고 새 테스트 파일로 검증한다(P0-3 규칙).

**비목표**

- 통합 스튜디오/새 전역 작성 화면.
- SSO·OTP·기업 로그인 구현(Google 로그인도 보류 상태 — `docs/plan.md` §1 인증 방향).
- 이 계획에서 서버 작업 큐·과금·실제 영상 렌더 인프라를 완성하는 것(S4는 인터페이스·최소 연동까지).
- 임의 HTML/CSS/JS를 실행하는 사용자 템플릿.

## 2. 공통 구조

```
┌ AI 패널(공통) ─────────────┐ ┌ 캔버스(종류별) ─────────────┐
│ 템플릿 갤러리               │ │ 문서: 페이지                  │
│ 질문 카드                   │ │ 슬라이드: 덱                  │
│ 브리프/개요 승인 카드        │ │ 영상: 미리보기·플레이어·장면   │
│ 생성 진행 카드               │ │                              │
│ 검토/QC 목록 · 편집 큐       │ │                              │
│ 입력창(AiComposer, 기존 공유)│ │                              │
└─────────────────────────────┘ └──────────────────────────────┘
```

공통 컴포넌트(`packages/ui`, 신규 파일 — counted 아님):

| 컴포넌트             | 역할                                                                    | 종류별 차이           |
| -------------------- | ----------------------------------------------------------------------- | --------------------- |
| `ClarifyCard`        | 질문 2~4개, 선택지, 건너뛰기                                            | 없음(스키마만)        |
| `BriefCard`          | 스타일 타일·방향, 섹션/페이지/장면 목록 편집, "이대로 생성/다른 브리프" | 브리프 스키마         |
| `GenerationProgress` | 단계 모델 `{key,label,status,done,total}`, 중지, 부분 결과 유지         | 단계 이름             |
| `TemplateGallery`    | 카드 그리드·표지·분류/필터 칩                                           | 템플릿 데이터·필터 축 |
| `EditQueueCard`      | 요소/블록별 지시 모아 제출                                              | 대상 단위             |
| 공통 문자열          | 새 UI 문구를 **한 파일**에 21개 언어로                                  | 없음                  |

기존 공유: `AiComposer`, `AiScopeQuote`, `AiQueueStrip`, 모델 선택, 사용량·구독 UI, send gate.
종류별로 남길 것: 브리프 스키마, 생성 도구/프롬프트, 검증·QC, 내보내기.

## 3. 훅 예산

- **counted = 업스트림 파일 수정/삭제 파일 수**(줄 수 아님). 신규 파일은 원장에 등록하되 counted에 넣지 않는다.
- 각 슬라이스는 머지 전에 `npm run check:upstream`으로 확인하고, 배정치를 넘으면 **먼저 보고**한다.

| 슬라이스       | counted 배정 | 누적  | 비고                     |
| -------------- | ------------ | ----- | ------------------------ |
| 기준선         | —            | 78    | 현재 main                |
| S1 공통 + 문서 | +3~4         | 81~82 | 초과 시 슬라이스 중단    |

## 4. 슬라이스

### S1 — 공통 컴포넌트 + 문서 흐름

**범위**: `packages/ui`에 공통 카드·진행·갤러리·문자열을 추가하고, docs 앱에 템플릿→질문→브리프 승인→생성→QC를 연결한다.

**산출물**

- 공통 컴포넌트·CSS·새 문자열 파일(신규).
- 문서 템플릿 데이터(예: 보고서·회의록·제안서)와 브리프 스키마(섹션·길이·대상·톤).
- 질문·브리프 도구(`ask_clarification`, `plan_document`)와 생성 진행 이벤트.
- 문서 QC(맞춤법·일관성·페이지 나눔) 최소 규칙.

**업스트림 수정 (counted +3~4)**

- `apps/docs/src/renderer/ai/AiPanel.tsx` — 상태·카드 렌더·도구 연결
- `apps/docs/src/renderer/ai/docs-skill.ts` — 새 도구 등록
- `apps/docs/src/renderer/styles.css` — 패널 레이아웃 보정(공통 CSS로 흡수 가능하면 생략)
- (선택) `apps/docs/src/renderer/App.tsx` — 확정 브리프 고정

**테스트**: 카드/진행/갤러리 단위, 질문→브리프→생성→QC 흐름, 렌더러 스냅샷에 비밀값 없음, 기존 docs 스위트 유지.
**되돌리는 방법**: 새 공통 파일·템플릿 데이터를 삭제하고 docs 수정 3~~4곳을 원복.
**추정**: 2~~3주.

### S2 — 슬라이드에 개요 승인 + 공통 컴포넌트 교체

**범위**: slides의 질문·진행·갤러리를 공통 컴포넌트로 바꾸고, 계획 단계에 **개요 승인 카드**를 추가한다. 기존 생성·QC·부분 유지 동작은 그대로.

**산출물**

- 인라인 `ClarifyCard`·`TemplateGallery`를 공통 구현으로 교체(동작 동일).
- 진행 카드를 공통 `GenerationProgress`로 교체.

**업스트림 수정 (counted +3)**

- `apps/slides/src/renderer/ai/AiPanel.tsx`
- `apps/slides/src/renderer/ai/slides-skill.ts`
- `apps/slides/src/renderer/ai/TemplateGallery.tsx` (공통 갤러리 래퍼)

**테스트**: 개요 승인/취소, 공통 카드 패리티, 기존 deck 생성·QC 회귀, e2e 템플릿→생성.
**되돌리는 방법**: 세 파일의 카드 교체·승인 호출을 원복하고 공통 컴포넌트 의존을 제거.

### S4 — SaaS 템플릿 레지스트리 + 모델 게이트웨이

**범위**: 서명된 원격 템플릿 매니페스트를 받아 공통 갤러리에 공급하고, 모델 호출을 SaaS 게이트웨이로 보낼 수 있는 어댑터와 사용량 이벤트를 추가한다. 작업 큐·아티팩트 저장·실제 영상 렌더는 후속.

**산출물**

- `TemplateRegistry` 클라이언트: `list/get(version, sha256)`, 서명·해시 검증, 캐시, 오프라인 폴백.
- `ModelGateway` 어댑터: 기존 `ai:stream` 관문에서 테넌트 단기 토큰으로 중계. 사용자 구독·BYOK 경로는 유지.
- 사용량 이벤트 `{tenant,user,job,kind,units}` 최소 카운터(과금 아님).
- 테넌트 설정 확장: 템플릿 카탈로그 URL/공개키, 모델 게이트웨이 ID·참조(비밀값은 참조만).

**업스트림 수정 (counted +0~1)**

- 템플릿 소비는 S1/S2에서 이미 수정한 패널 파일을 재사용.
- 모델 게이트웨이는 S3에서 수정한 `apps/shell/src/main/index.ts`의 `ai:stream` 관문을 재사용.
- 필요 시 `packages/ai-provider/src/*` 1곳(+1) — 그 전에 보고.

**테스트**: 매니페스트 서명·해시·버전 거부, 캐시/오프라인, 게이트웨이 성공·거부·만료, 사용량 이벤트, 렌더러에 토큰 없음.
**되돌리는 방법**: 새 클라이언트·설정 필드를 제거하고 `ai:stream`을 기존 경로로 원복.
**추정**: 2~3주(서버 측 최소 API 포함, 인프라 승인 후).

## 5. 영상에서 HyperFrames 기능 살리기

HyperFrames는 HTML 기반 모션 그래픽을 영상으로 렌더하는 엔진으로 본다. 문서/슬라이드와 같은 흐름을 유지하면서 다음만 다르게 한다.

1. **템플릿 = 컴포지션 + 변수 스키마**
   - 각 템플릿이 편집 가능한 변수를 선언한다: `text`, `number`, `select`, `color`, `media`, `list`(장면/항목).
   - **질문 폼은 변수 스키마에서 자동 생성**한다. 스키마에 없는 것은 묻지 않는다.
2. **장면 목록 = 블록 목록**
   - 장면/블록마다 변수 값·길이·전환을 가진다. 순서 변경·삭제·복제는 블록 편집으로 처리한다.
   - 브리프 승인 카드에는 장면 목록과 각 장면의 변수 요약을 보여 준다.
3. **미리보기·렌더 진행**
   - 선택한 장면/블록을 HTML로 미리보기하고, 렌더는 서버 작업으로 제출한다.
   - 공통 `GenerationProgress`에 `장면 구성 → 렌더 → QC → 완료`를 매핑하고 취소·부분 결과를 지원한다.
4. **한계 표시**
   - 변수로 노출된 값만 바꿀 수 있다. 레이아웃·애니메이션·임의 CSS/JS는 편집 불가임을 브리프 카드와 편집 화면에 명시한다.
   - 고정: 화면 비율, 폰트 세트, 최대 길이, 안전 영역. 초과 텍스트·장면 길이는 생성 전 검증에서 막는다.
5. **보안**
   - 템플릿은 서명·해시 검증된 것만 사용하고 원격 코드를 실행하지 않는다. 렌더 입력은 스키마 검증을 통과한 값만 보낸다.

## 6. 공개 문서 범위

- 이 문서의 모든 내용은 공개 가능한 일반 설계다. 내부 회사명·도메인·경로·정책 값·템플릿 이름은 쓰지 않는다.
- HyperFrames는 외부 엔진 이름으로만 언급하고, 내부 구현·번들·경로는 적지 않는다.

## 8. 위험 · 열린 질문

- 훅 예산이 빠듯하다. S1~S3에서 배정을 넘기면 S4를 새 파일만으로 구현하거나 상한 상향 승인이 필요하다.
- 영상 렌더는 로컬에 없어 서버·큐·스토리지가 선행 조건이다. S3는 mock으로 계약만 고정한다.
- 템플릿 제작·승인 도구가 없다. 초기 템플릿은 개발자가 코드로 추가하고, 큐레이션 UI는 후속.
- 문서 데이터 경계: 무엇을 모델/서버로 보내는지(전문 vs 선택 블록), 보관·삭제 정책을 S4 전에 확정해야 한다.
- 영상 장면 편집의 범위(변수만 vs 타임라인)는 S3 결과를 보고 결정한다.
- web의 화면 캡처가 오면 S1·S2 카드 배치와 영상 캔버스 목업에 반영한다.
